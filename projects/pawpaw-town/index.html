Pawpaw Town

고양이가 움직이는 모습을 만들고 나니, 발이 바닥에서 미끄러졌습니다.

작업실, 주방, 다락방을 돌아다니는 Unity 게임을 만들고 있습니다. 캐릭터 움직임과 방의 조명, 화면 설정을 직접 시험하며 고쳐왔습니다.

어떻게 시작했나

고양이를 직접 움직여 집 안을 탐험하는 게임을 생각했습니다. 화면 위에서 고양이가 단순히 이동하는 데서 끝나지 않고, 주변 물건에 부딪히고 뛰어올라야 게임 같을 것 같았습니다.

Unity에서 고양이의 이동, 점프, 오브젝트와의 상호작용을 작업했습니다. 같은 캐릭터라도 방에 따라 움직일 공간과 물건이 달라져서 작업실과 주방, 다락방의 장면을 따로 만들었습니다.

걸을 때 발이 미끄러지던 문제

처음에는 이동 속도와 걷기 애니메이션 속도를 대략 맞췄습니다. 그런데 캐릭터가 벽에 막혀도 다리를 계속 바쁘게 움직이고, 회전할 때에는 옆으로 미끄러지는 모습이 보였습니다. 숫자만 맞춘다고 자연스러운 걸음이 되는 건 아니었습니다.

먼저 이동 속도를 늦추고 실제 이동한 거리로 발걸음 애니메이션의 진행을 계산했습니다. 그다음에는 캐릭터마다 발의 접지 움직임이 달라 같은 속도를 적용할 수 없다는 점을 확인했습니다. 현재는 각 캐릭터의 발이 바닥에 닿은 구간을 살펴 걸음 속도를 따로 맞춥니다.

걸음이 조금씩 나아지는 과정이 눈에 잘 드러나서 재미있었습니다. 코드 안의 속도 값보다 화면에서 실제로 어떻게 걷는지 보는 일이 중요했습니다.

세 방을 만들면서 발견한 것

작업실과 주방, 다락방을 꾸밀 때는 소품이 예쁘게 보이는 것만으로는 부족했습니다. 카메라가 가까워지면 선반이나 바닥판의 겹친 면이 깜빡이고, 방 가장자리의 그림자가 사라지는 경우가 있었습니다.

겹친 바닥판은 면이 맞닿게 다시 만들었고, 그림자가 사라지는 거리는 방의 크기와 카메라 위치를 보고 계산했습니다. 캐릭터 눈의 무늬가 단색으로 바뀌는 문제도 원래 텍스처를 연결하는 방식으로 고쳤습니다.

조명이나 카메라를 수정한 뒤에는 세 방을 직접 돌아보며 다른 장면이 망가지지 않았는지 확인했습니다.

만들면서 바뀐 생각

처음에는 이 게임을 팀 프로젝트 주제로도 검토했습니다. 팀원들과 다른 주제들을 비교한 끝에 팀에서는 학업 관리 앱을 만들기로 했고, Pawpaw Town은 제가 개인적으로 진행한 프로토타입으로 남았습니다.

아직 출시한 게임은 아니지만, 여러 방을 실제로 움직여 볼 수 있도록 만들어둔 영상이 있습니다. 아래 영상은 각각 다른 맵에서 촬영했습니다.

게임을 켜놓고 두니 컴퓨터가 계속 바쁘게 일했습니다

장면이 복잡하지 않은 메뉴에서도 게임이 가능한 만큼 빠르게 화면을 그리면서 불필요하게 자원을 쓰고 있었습니다. 플레이 화면은 60프레임, 메뉴는 30프레임을 기본으로 제한하고 화질과 동기화 옵션을 메뉴에서 조절하게 했습니다.

이후에는 실제 게임 화면에서 사용하지 않는 전체 화면 합성 작업도 걷어냈습니다. 코드를 지우면서 같은 장면이 그대로 보이는지 화면을 비교했고, 성능 측정으로 차이도 확인했습니다.
