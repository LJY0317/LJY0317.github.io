프로젝트와 담당 업무

Project and role

시간표와 일정, 필기, 스티커를 관리하는 학생용 앱입니다. 팀원들과 Flutter로 개발했습니다. 저는 공통 화면과 반응형 UI, 시간표 사진에서 수업을 읽는 기능, 에브리타임 공유 링크 가져오기와 관련 API를 맡았습니다. 필기와 스티커를 포함한 앱 전체 화면은 팀의 작업입니다.

Dayori is a Flutter app for timetables, schedules, notes, and stickers. I worked on shared and responsive screens, timetable OCR, Everytime link imports, and the related APIs. The complete app, including its note and sticker features, was built by the team.

개발 방식에 대한 의견 차이

Choosing a development approach

저는 기기마다 익숙한 화면과 동작을 살리기 위해 아이폰과 안드로이드 앱을 따로 만들고 싶었습니다. 팀원들은 Flutter로 함께 개발하는 편을 선호했습니다. 고양이 게임과 가상 피팅 등 여러 주제를 검토하는 동안 시간이 지나, 전체 8주 중 실제 앱 개발에 쓸 수 있는 기간은 4주도 남지 않았습니다.

I preferred separate iPhone and Android apps, while teammates favored Flutter. We had considered several topics, including a cat game and virtual fitting, leaving fewer than four weeks of an eight-week project for the final app.

두 앱을 따로 만들면 화면 작업과 오류 수정도 각각 해야 했습니다. 남은 시간을 고려해 Flutter로 진행하기로 했고, 저도 공통 화면과 시간표 가져오기 기능을 그 방식으로 구현했습니다.

Separate apps would also require separate screen and bug-fix work. We chose Flutter for the remaining schedule, and I implemented my screens and import features in it.

시간표 이미지 인식 수정

Reworking timetable OCR

처음에는 사진 전체에서 글자와 위치를 읽어 과목을 묶었습니다. 시간표에는 수업명 외에 요일과 시간 눈금도 들어 있어, 전체 이미지에서 읽은 문구가 서로 다른 수업의 후보로 섞이는 문제가 있었습니다.

The first OCR version grouped subjects from text and positions across the entire image. Day labels, time markers, and subject names could become mixed candidates.

색상으로 구분된 수업 칸을 먼저 찾고 각 칸을 잘라 따로 읽는 방식으로 변경했습니다. 전체 이미지의 인식 결과는 요일과 시간 눈금의 기준을 얻는 데 사용하고, 과목명과 장소는 잘라낸 칸의 결과를 우선하도록 했습니다. 읽어온 수업은 저장하기 전에 이름과 요일, 시간을 수정할 수 있게 했습니다.

I changed it to detect colored class blocks and run OCR on each crop. Full-image recognition supplied day and time anchors, while subject and location candidates came primarily from the blocks. Users can edit the extracted name, day, and time before saving.

공유 링크와 팀 코드 병합

Link imports and merging team changes

에브리타임 공유 링크는 서버에서 수업 목록으로 변환해 앱으로 전달했습니다. 잘못되거나 비공개인 링크는 오류를 구분해서 알려주고, 정상적으로 읽은 결과도 저장 전 확인하도록 했습니다.

The backend converts Everytime sharing links into proposed classes, distinguishes invalid or private links, and returns successful results for review before saving.

팀의 최신 코드를 제 작업과 합칠 때는 시간표 화면과 API 연결이 충돌했습니다. 최신 목록·수정·삭제 기능을 유지하면서 펜 입력 연결과 공통 상단 메뉴를 다시 붙였고, 사용하지 않는 목업 화면은 정리했습니다. 제 기능이 동작하는 것과 팀의 다른 기능을 함께 유지하는 일을 같이 확인해야 했습니다.

Merging my changes with the team code caused timetable UI and API conflicts. I retained the current list, edit, and delete flows, reattached pen-input and shared-header hooks, and removed an unused mock screen.
