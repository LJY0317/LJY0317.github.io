Context

What the team built

Dayori combined timetable and calendar management with planner, note, handwriting, sticker, and gallery features. The wider product also included backend services, storage, authentication, and infrastructure.

Scope boundaryThe cover and wider product media show the team application. My contribution is limited to the work described below.

Responsibility

What I worked on

The project README assigns me three areas: shared UI tokens and responsive UX, timetable OCR and Everytime import, and the backend APIs that support those import flows.

Problem

Imported timetable data can contain missing or ambiguous fields. The product therefore needs a clear review step before saving structured schedule data.

Action

  • Implemented imports from timetable images and Everytime shared links.
  • Routed imported results through preview and review screens before saving.
  • Worked across Flutter and the related backend endpoints to validate each flow from input to structured timetable.
  • Contributed shared UI tokens and responsive behaviour across the frontend.

Result

The selected evidence shows both import paths and the resulting timetable. Wider product screens appear separately so they are not mistaken for my individual work.
