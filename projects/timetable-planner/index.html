시간표 사진 한 장으로 수업을 가져오는 학생용 플래너.

시간표, 일정, 필기, 스티커를 한 곳에서 관리하는 앱입니다. 시간표 이미지와 에브리타임 공유 링크에서 수업을 가져오는 기능을 작업했습니다.

두 앱을 따로 만들고 싶었지만

저는 iOS와 Android를 각각 개발하면 화면과 동작을 더 세밀하게 다룰 수 있을 거라고 생각했습니다. 반면 팀원들은 Flutter로 함께 만들자고 했습니다. 이미 여러 주제를 검토하느라 시간이 지나 8주 중 남은 개발 기간이 4주도 되지 않았습니다.

시간 안에 두 앱을 각각 만들고 수정할 수 있을지 생각해보니 팀원들의 말이 이해됐습니다. 결국 Flutter를 선택했고, 저는 그 안에서 공통 화면과 반응형 UI를 작업했습니다.

시간표 사진은 생각보다 읽기 어려웠습니다

처음에는 사진 전체에서 글자를 읽고 각 과목의 이름과 시간을 찾아보려 했습니다. 하지만 실제 시간표에는 색깔로 나뉜 수업 칸과 요일·시간 눈금이 함께 있어서, 글자만 읽으면 서로 다른 과목이 뒤섞일 수 있었습니다.

그래서 인식된 글자를 바로 저장하지 않고, 먼저 후보 목록을 보여주고 이름과 시간 등을 사용자가 수정할 수 있게 했습니다. 그 뒤에는 이미지의 색상별 수업 칸을 먼저 찾고, 각 칸을 잘라서 글자를 읽는 방식으로 바꿨습니다. 요일과 시간 눈금은 따로 읽어 기준으로 삼았습니다.

처음 만들었던 전체 이미지 OCR도 무조건 버리지는 않았습니다. 수업 칸을 찾기 어려울 때 사용할 보조 경로로 남겼습니다. 그 과정에서 시간표처럼 그림과 글자가 섞인 자료는 글자만 잘 인식한다고 끝나는 일이 아니라는 걸 배웠습니다.

에브리타임 링크도 저장 전에 확인하도록

사진뿐 아니라 에브리타임에서 공유한 시간표 링크를 넣는 기능도 만들었습니다. 서버에서 공유 페이지를 읽어 수업 목록으로 바꾸고, 앱에는 저장하기 전 후보로 돌려줍니다.

처음부터 링크가 잘못됐거나 비공개 상태인 경우도 있어서 그런 경우를 구분해 오류를 돌려주게 했습니다. 사용자가 자료를 가져와도 바로 저장하지 않고 내용을 먼저 보는 흐름을 유지했습니다.

시간표를 직접 입력하지 않게

학생이 시간표를 일일이 입력하는 대신 이미지나 에브리타임 링크를 넣으면 과목 정보를 가져오도록 만들었습니다. 이미지 인식 결과가 항상 정확하지 않을 수 있어, 저장하기 전에 미리 보고 수정하는 화면을 거치도록 했습니다.

화면만 만드는 일이 아니었습니다. OCR과 링크 입력, 서버의 관련 API를 맞추면서 사용자가 실제로 저장할 때까지 이어지는 흐름을 확인했습니다.

팀 코드를 합칠 때도 일이 생겼습니다

각자 화면과 API를 작업하다 보니 팀의 최신 코드와 제 작업 브랜치를 합치는 과정에서 충돌이 났습니다. 예전 화면 상태를 그대로 살리면 최신 시간표 저장 기능이 빠지고, 최신 코드만 받으면 제가 작업하던 화면 연결이 끊어질 수 있었습니다.

최신 시간표 API의 목록·수정·삭제 기능을 기준으로 두고, 제가 작업한 화면의 펜 입력 연결과 공통 상단 메뉴를 다시 붙였습니다. 더 이상 쓰이지 않는 목업 화면 파일은 제거했습니다. 제 작업만 고집해서는 앱 전체가 돌아갈 수 없겠다는 걸 실감했습니다.

작업 기록

사진 전체에서 텍스트와 위치를 읽어오는 첫 OCR 기능을 구현했습니다.

OCR로 찾은 수업을 바로 저장하지 않고 수정하는 화면을 만들었습니다.

글자가 섞이자 색상별 수업 칸을 먼저 자르는 방식으로 다시 만들었습니다.

에브리타임 공유 링크에서 수업 후보를 가져오는 서버 기능을 만들었습니다.

팀의 최신 시간표 API와 제 화면 변경을 합치면서 생긴 충돌을 정리했습니다.
