프로젝트와 담당 업무

Project and role

작업자가 화면에서 식물을 선택하면 로봇이 이동하고 작물 상태를 확인하는 프로젝트입니다. 팀원들과 작물 선택 화면과 로봇 시스템을 연결했습니다. 저는 이동 목표와 경로 계산, 지도·주행 실험을 맡았습니다. 온실과 로봇은 Gazebo에서 시뮬레이션했고, 지도와 이동 상태는 RViz에서 확인했습니다.

The team connected an operator interface to a simulated greenhouse robot. Selecting a plant sends the robot to inspect it. I worked on navigation goals, route calculation, and mapping and driving tests in Gazebo and RViz.

이동 목표 변경과 복구

Changing and reverting the goal

식물을 선택해도 로봇이 통로 중앙에 멈추는 점이 아쉬웠습니다. 식물 가까이에서 상태를 확인하도록 마지막 목적지를 옮겼습니다. 처음에는 목표 좌표를 조금 바꾸는 작업이라고 생각했습니다.

The robot stopped in the middle of the aisle. I changed the final goal to bring it closer to the selected plant, initially treating it as a small coordinate change.

Gazebo에서 실행하니 반대편 통로를 경유하거나 충돌 경고가 나왔고, 출발 지점이 점유됐다는 오류도 생겼습니다. 우선 변경을 되돌려 기존 경유점 방식으로 복구했습니다. 문제가 난 상태에서 좌표를 계속 조정하지 않고, 이전 방식과 실행 기록을 비교했습니다.

In Gazebo, the robot detoured through the opposite aisle and produced collision and occupied-start warnings. I reverted the goal change and compared the logs against the previous waypoint route instead of continuing to tune the failing version.

위치 정보와 출발 경유점 수정

Pose age and the first waypoint

실행 기록에서는 최종 목표보다 경로 계산에 사용한 현재 위치가 문제인 경우를 확인했습니다. 예전에 저장한 위치를 사용하면 로봇이 이미 지난 줄을 기준으로 경로가 잘렸습니다. 기록 시각을 검사해 오래된 위치는 현재 위치로 쓰지 않도록 수정했습니다.

The logs pointed to the position used for route calculation, not only the final goal. An old snapshot could make the route start from a row the robot had already passed. I added a timestamp check before using a saved pose.

같은 통로에서 목표와 반대 방향의 지점을 먼저 출발 경유점으로 고르는 경우도 있었습니다. 목표가 현재 위치보다 위에 있으면 위쪽 후보를, 아래에 있으면 아래쪽 후보를 우선하도록 선택 방식을 바꿨습니다.

The first waypoint could also be behind the robot relative to its target. I made selection prefer candidates in the target direction within the same aisle.

수정 후 확인한 항목

What I checked after the changes

오래된 위치를 사용하지 않는 테스트에서는 10초 전 위치 기록을 만들고, 유효 시간을 1.5초로 설정했을 때 현재 위치로 반환되지 않는지 확인했습니다. 목표 근처에 있다는 오래된 기록만으로 이동이 완료됐다고 판단하지 않는 경우도 검사했습니다.

A pose test creates a ten-second-old snapshot and confirms it is rejected with a 1.5-second age limit. Another test ensures a stale position near the goal does not make a failed navigation count as complete.

경유점 테스트에서는 같은 통로의 위쪽 목표를 선택했을 때 아래쪽 점을 먼저 고르지 않는지 확인했습니다. 수정 커밋에는 관련 Python 테스트 37개와 프론트엔드 타입 검사, 실행 패키지 재빌드를 확인한 기록이 남아 있습니다.

The waypoint test checks that a target farther up the aisle does not first select a point below the robot. The change record includes 37 related Python tests, a frontend type check, and a rebuild of the robot startup package.

목표 좌표 변경, 기존 방식으로 복구, 위치와 경유점 보정을 별도 변경으로 남겼습니다. 처음에는 도착 위치를 고치려 했지만, 실제 원인을 찾는 동안 경로를 계산하기 전의 입력값까지 살펴보게 됐습니다.

The goal adjustment, revert, and pose/waypoint fixes were separate changes. Investigating the final stop led me back to the inputs used before route calculation.
