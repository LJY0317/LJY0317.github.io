# Portfolio site

This repository publishes Lee Jaeyup's personal and team project portfolio as static HTML, CSS, and JavaScript.

## Layout
- Use a pure white background (#ffffff), dark text, and a single readable column on every viewport.
- Keep body text in one readable column, but use deliberate typography, compact navigation, generous media, and a clear visual hierarchy. The user wants a polished product portfolio rather than unstyled document HTML. Keep the page white; avoid decorative panels, marketing cards, and oversized slogans. Media frames and concise project navigation are useful when they aid browsing.
- Keep only one personal name in the home header; use a content title below it. Project names are headings. Subheadings describe the actual work, such as navigation recovery or timetable OCR. Do not use dramatic incident headlines or slogans.
- Korean body paragraphs may be justified; keep captions and navigation simple. Check mobile line breaks and overflow.

## Content
- Explain what the product does, what Lee worked on, what failed, and what changed. Use source material and commit history for specific claims.
- Distinguish the team product from personal work in ordinary prose. Do not invent teammate assignments, meetings, outcomes, measurements, or personal feelings.
- Keep meaningful technical detail. Remove repeated explanations, forced lessons, self-praise, and defensive meta-copy.
- Korean and English should each read naturally. Preserve equivalent facts and project scope rather than translating word for word.
- A short development status is enough for unfinished work. Do not attach disclaimers to every paragraph.

## Media and code
- Use actual approved project captures. Preserve existing media paths and project URLs.
- Keep video silent, looping, inline, and viewport-triggered. Pause offscreen and hidden-tab video, honor reduced motion and manual pause, and provide a poster.
- Keep visible keyboard focus, semantic links and buttons, intrinsic image dimensions, and readable contrast.
- This site has no build requirement. Prefer one small stylesheet and script over layered overrides or added frameworks.
- Review desktop and narrow mobile layouts and check asset paths, language switching, and playback before publishing.
- Keep private paths, credentials, original unreviewed captures, and temporary review files out of Git.
